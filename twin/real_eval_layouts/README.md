# Real-robot evaluation: fixed scenes from the twin

Twenty Task 1 scenes (plus five spares), and ten Task 2 scenes, built in the DOFBOT twin, to be rebuilt on the real table so every method is run
on the same arrangements. Generated by `python -m twin.make_eval_layouts` (seed 20261006; rerunning gives the same
layouts).

| file | what |
|---|---|
| `<id>.png`, `layouts.pdf` | one sheet per scene: to-scale top view, build order, expected arm-camera views |
| `scenes.yaml`, `scenes_spares.yaml` | Task 1: the 20 eval scenes in run order, and the 5 spares |
| `scenes_task2.yaml`, `scenes_task2_spares.yaml`, `layouts_task2.pdf` | Task 2 (below) |
| `layouts.json` | twin state of each scene and the search's answer (`optimal_steps`, `first_choices`, `plan`) |

## The scenes

| kind | eval | spares | blocks | what | steps at best |
|---|---|---|---|---|---|
| `C1` | 10 | 2 | 3 (odd ids) or 4 (even) | one block lies on the target | 2 |
| `C2` | 6 | 2 | 4 | two blocks lie on the target | 3 |
| `F` | 4 | 1 | 4 | the target is free (control) | 1 |

- Each colour is the target 4-6 times and the first block to remove 3-5 times, so no colour is the answer more
  often than another.
- A layout was kept only if the search's step count and its best first choices stayed the same over 8 rebuilds
  with hand-placement noise (4 mm, 5°). A copy placed within about half a centimetre has the same answer.
- No model was run to choose the scenes.
- In all 16 covered eval scenes the target is partly visible from the arm camera (12-53% of its pixels). Only spare
  `C2-08` hides it fully.

## Before the first scene

1. No sheet, no AprilTags on the blocks (tape over them), the lighting of the `no_sheet` capture or brighter.
2. Mark the workspace rectangle on the table. Positions on the sheets are in cm from the far edge and the left
   edge of a US-Letter rectangle (21.6 cm wide, 27.9 cm deep) lying where the white sheet used to lie: in the camera
   image at the home pose its far corners are at pixels (88, 71) and (501, 38). Lay a Letter sheet there, mark the
   two far corners and the left edge with tape, and take the sheet away. To check the marks, save one frame of the
   empty table and draw the rectangle on it (white lines every 5 cm; the far-left corner is the origin):

   ```bash
   python -m twin.make_eval_layouts --check grid --frame <frame.jpg>
   ```

## Building a scene

Follow the numbered rows on the sheet: the target first (the runner takes its reference photo with only the
target on the table), then the other table blocks, then the block(s) on the target. Compare with the two expected
camera views. To check a built scene against its layout, draw the expected block edges on the frame the server
saved for it:

```bash
python -m twin.make_eval_layouts --check C1-03 --frame save/real_eval/<session>     # newest frame of the session
```

If a layout cannot be built (a stack will not stand) or the arm cannot reach it, replace it with the next unused
spare of the same kind for every method, and note it.

## Run order and commands

One method per session: start the lab-PC server for a method, run all 20 scenes, then switch method. The scene
is rebuilt from its sheet for every method. `scenes.yaml` is in run order, with the three kinds spread over the
session. Commands: `docs/real_eval_commands.md`.

## Task 2: two targets in order

`scenes_task2.yaml` (10 scenes, 2 spares in `scenes_task2_spares.yaml`), sheets `T2a-*.png` and `T2b-*.png`,
`layouts_task2.pdf`. Four blocks each; both targets start covered and the first must be retrieved first.

| kind | eval | spares | what | steps at best |
|---|---|---|---|---|
| `T2a` | 6 | 1 | each target lies under its own block | 4 |
| `T2b` | 4 | 1 | the targets lie side by side under one block | 3 |

Kept with the same rule as Task 1: the step count and the best first choice hold over 8 noisy rebuilds. While the
first target is being retrieved the second may not be removed. These scenes have not been run in the twin.

## The same scenes in the twin

```bash
python -m twin.eval --layouts twin/real_eval_layouts/layouts.json --out save/twin_eval/real_layouts \
    --il-ckpts save/sre_twin2/sre_exit_it2.pt
```

Result (`save/twin_eval/real_layouts/summary.txt`, ideal removal, a grasp at a still-covered target fails):

| method | success | covered (16) | free (4) | in the best number of steps |
|---|---|---|---|---|
| search (optimum) | 20/20 | 16 | 4 | 20 |
| SRE, expert iteration in the twin (it2) | 18/20 | 14 | 4 | 17 |
| SRE, imitation only | 15/20 | 11 | 4 | 5 |
| SRE, PPO | 11/20 | 7 | 4 | 4 |
| random | 11/20 | 7 | 4 | 4 |
| heuristic (Alg. 1) | 9/20 | 5 | 4 | 8 |
| always grasp the target | 4/20 | 0 | 4 | 4 |

These are the twin's predictions for the real table, scene by scene (`episodes.jsonl`, `scene` = layout id). GPT-4o
was not run in the twin.
